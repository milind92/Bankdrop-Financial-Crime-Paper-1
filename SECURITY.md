# Security And Privacy Reporting

## Do Not Disclose Sensitive Material Publicly

Do not open a public issue, discussion, pull request, or attachment containing raw research material, screenshots, OCR text, source paths, identifiers, handles, URLs, credentials, record-level validation material, controlled-access instructions, or operational details.

## Private Reporting

Use GitHub’s private vulnerability-reporting feature if it is enabled. Otherwise send the repository owner only a non-sensitive request for a private reporting channel. Do not include the suspected controlled material in that initial request.

A private report should identify the affected repository path or commit, describe the risk without reproducing sensitive content, state whether the material appears public, and provide safe contact details.

## Maintainer Response

Maintainers should assess exposure promptly, restrict access where necessary, preserve minimum incident evidence, remove exposed material from the current release and reachable history where required, notify the responsible authors or institutions, rotate credentials where applicable, and rerun the repository integrity checks.

## Research-Safety Boundary

The repository contains public code, documentation, and aggregate outputs only. Public visibility does not authorise access to or redistribution of excluded controlled material. Controlled-access questions are governed by [DATA_AVAILABILITY.md](DATA_AVAILABILITY.md).
